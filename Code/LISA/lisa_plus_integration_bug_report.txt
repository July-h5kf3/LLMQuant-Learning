====================================================================
一、LISA 与 LISA++ 的代码差异概览（基于 /root/autodl-tmp/LISA 的 main..lisa_plus）
====================================================================
1. LISA++ 主要新增模块
- 新增整套 `model/llava1p5/**`（language model、serve、train、mpt）
- 新增 `chat_instance.py`
- 训练/数据处理核心改动集中在:
  - model/LISA.py
  - utils/dataset.py
  - utils/sem_seg_dataset.py
  - utils/vqa_dataset.py
  - utils/utils.py

2. 对你当前复现仓库的含义
- 不是“改几行”级别，需要按“并行接入 + 渐进切换”做。
- 推荐先让 LISA(原) 与 LISA++ 两条路径并存，稳定后再默认切换到 LISA++。

====================================================================
二、LISA++ 整合到当前复现仓库的推荐路径
====================================================================
Phase 1: 并行引入，不破坏现有 LISA 路径
- 新增目录: `model/llava1p5/`（整体拷贝）
- 保持现有 `model/llava/` 不动
- 在 `model/LISA.py` 中增加可配置切换:
  - 例如 `llava_backend: llava|llava1p5`
  - 默认先维持 `llava`，避免一次性切换导致训练/推理不可用

Phase 2: 对齐 LISA++ 关键行为（非量化）
- 合并 `model/LISA.py` 的以下能力:
  - 动态 image token 长度（替代写死 255）
  - Hungarian matcher + change_list 对齐（实例分割）
- 合并数据侧:
  - `utils/dataset.py` 的 `change_list`、`semantic_ids_list`
  - `ValDataset` 的 `ReasonInstanceSeg` 路径
  - `utils/sem_seg_dataset.py` 的多类别问题模板与采样
  - `utils/vqa_dataset.py` 的多数据源路径鲁棒性处理

Phase 3: 配置与回归
- 扩展 YAML:
  - train/test 配置增加 `llava_backend`、实例分割相关开关
- 最小回归集建议:
  1) 单卡 train 10~20 step（ReasonSeg）
  2) val 推理 10 张图（ReasonSeg）
  3) ReasonInstanceSeg 样例 1 组
  4) chat 推理 2 张图（含多实例询问）

三、已修复仓库 vs 当前复现仓库：Bug/风险差异（非量化）
====================================================================
说明: 下列项是“当前复现仓库缺失、已修复仓库已实现”的关键差异。

[高优先级]

1) 固定 255 图像 token 的硬编码风险（分辨率变化即错位）
- 当前复现:
  - model/LISA.py:175, 178, 350
  - 直接补 `255` 个 False 构造 seg_token_mask
- 已修复:
  - /root/autodl-tmp/LISA/model/LISA.py:300, 303, 482, 485
  - 按 `image_token_len=(H//14)*(W//14)` 动态计算
- 影响:
  - 非默认分辨率/不同视觉塔 patch 规则时，[SEG] 对齐会错，导致 mask 对应错误。

2) 缺少实例级 GT-Pred 对齐（Hungarian）
- 当前复现:
  - model/LISA.py 无 `hungarian_matcher*`，无 `change_list` 入参与处理
- 已修复:
  - /root/autodl-tmp/LISA/model/LISA.py:227, 245, 285, 405+
- 影响:
  - 多实例场景中，训练监督可能错配，损失和指标会抖动或失真。

3) 数据批处理缺少实例重排所需元信息
- 当前复现:
  - utils/dataset.py 无 `change_list`、`semantic_ids_list`
- 已修复:
  - /root/autodl-tmp/LISA/utils/dataset.py:205, 206
- 影响:
  - 即使模型端支持 Hungarian，也拿不到重排依据，实例监督无法闭环。

4) 缺少 ReasonInstanceSeg 验证分支
- 当前复现:
  - utils/dataset.py 无 `ReasonInstanceSeg` 路径
- 已修复:
  - /root/autodl-tmp/LISA/utils/dataset.py:346, 347, 397, 488, 608, 618
- 影响:
  - LISA++ 的实例分割验证流程无法在当前复现仓直接跑通。

5) `model/LISA.py` 中 LLaVA 后端仍是旧路径
- 当前复现:
  - model/LISA.py 使用 `.llava...`
- 已修复:
  - /root/autodl-tmp/LISA/model/LISA.py:13 使用 `.llava1p5...`
- 影响:
  - 当前代码并未真正接入 LISA++ 主干（只是 LISA 原版路径）。

[中优先级]

6) `llava_arch` 中图像起始 token 标签切片差异
- 当前复现:
  - model/llava/model/llava_arch.py:173
  - 使用 `cur_labels[image_token_start + 1 : image_token_start + 2]`
- 已修复:
  - /root/autodl-tmp/LISA/model/llava/model/llava_arch.py:182
  - 使用 `cur_labels[image_token_start : image_token_start + 1]`
- 影响:
  - 多模态拼接时 label 对齐存在偏移风险，可能导致训练目标错位。

7) 视觉塔 delay-load 下 dtype/device 属性鲁棒性不足
- 当前复现:
  - model/llava/model/multimodal_encoder/clip_encoder.py:61, 65
  - `dtype/device` 直接取 `self.vision_tower`
- 已修复:
  - /root/autodl-tmp/LISA/model/llava/model/multimodal_encoder/clip_encoder.py:67-76
  - 未加载时回退 `cfg_only` / CPU / float32
- 影响:
  - delay-load 场景下易触发属性访问错误或设备推断错误。

  - 支持 `llava_v1_5_mix665k`、OCR jpg/png、VG 路径改写

9) VQA 对话中缺少“纯文本回答”约束提示
