LISA 推理复现事项整理
======================

一、任务边界
------------
1. 只复现推理，不复现训练。
2. 以推理为主，但要把推理前所需的 fine-tuning / adapter 适配流程算入范围。
3. 不复现完整训练流水线，不复现大规模数据准备、训练采样、训练标签构造与 loss。
4. 优先对齐原始 LISA，再考虑 LISA++。
5. 目标不是直接运行旧仓库，而是提炼出适配较新环境的 PyTorch 推理实现。


二、为什么 TODO 要这样排序
------------------------
当前 TODO 的组织逻辑是：

1. 先做底座，再做上层
   - LISA 的上层能力依赖 LLaVA 先成功输出文本和 hidden states。

2. 先确认推理依赖的权重如何得到
   - 只有先理清哪些模块需要 fine-tune、哪些模块保持冻结，后面的推理实现才不会缺权重。

3. 先做输入链路，再做输出链路
   - 先保证图文输入正确进入模型，再去处理 [SEG] 和 mask。

4. 先做算法闭环，再做工程脚本
   - 先保证“文本输出 + mask 输出”成立，再考虑 demo、量化、服务化。

5. 先区分可复用与需重写模块，再进入编码
   - 避免把大量时间浪费在旧版依赖强耦合代码上。


三、按模块拆解
-------------
整个 LISA 复现可以分成 5 个模块：

1. LLaVA 模块
   - 负责图文输入组织、多模态特征拼接、语言生成、hidden states 输出。

2. fine-tuning / 权重适配模块
   - 负责确定哪些模块需要训练、权重如何保存、推理前如何合并或加载。

3. LISA bridge 模块
   - 负责从 [SEG] token 提取特征，并映射到 SAM prompt 空间。

4. SAM 模块
   - 负责将 prompt embedding 解码成最终 mask。

5. 推理脚本与后处理模块
   - 负责加载模型、组织输入、保存文本和可视化结果。


四、LLaVA 模块详细拆解
---------------------
如果你说“我要先复现 LLaVA 这一块”，那么至少要拆成下面几层。

4.1 LLaVA 相关文件及其作用
-------------------------
1. chat.py
   - 作用：最小推理入口。
   - 你可以把它看成“从用户输入到模型输出”的总流程样板。
   - 它展示了 prompt 组装、图像预处理、模型调用、结果保存。

2. model/llava/mm_utils.py
   - 作用：把文本 prompt 中的 <image> 转成特殊 image token。
   - 这是图文序列组织的第一步。

3. model/llava/conversation.py
   - 作用：定义对话模板。
   - 决定 prompt 最终长什么样，影响 tokenizer 输入内容。

4. model/llava/model/llava_arch.py
   - 作用：LLaVA 的核心多模态拼接逻辑。
   - 负责把 vision tower 输出的图像特征插入语言模型输入序列。
   - 这是最关键的文件之一。

5. model/llava/model/language_model/llava_llama.py
   - 作用：封装语言模型 forward / generate。
   - 同时负责返回 hidden states。
   - LISA 后面提取 [SEG] 特征时会依赖这里的输出行为。

6. model/llava/model/multimodal_encoder/clip_encoder.py
   - 作用：CLIP vision tower 封装。
   - 把图像转成给 LLM 使用的视觉特征。

7. model/llava/model/multimodal_encoder/builder.py
   - 作用：构建 vision tower。
   - 通常是辅助入口，不是第一优先级阅读对象。

8. model/llava/constants.py
   - 作用：定义 image token 等特殊常量。
   - 用来帮助理解 token 组织逻辑。

4.2 LLaVA 内部可以再拆成哪些子任务
--------------------------------
1. 输入组织
   - prompt 模板
   - <image> 占位符处理
   - tokenizer 编码

2. 图像编码
   - CLIP image processor
   - vision tower 前向
   - 视觉 token 生成

3. 多模态拼接
   - 将图像 token 插入文本 embedding 序列
   - 构造新的 attention mask
   - 对齐 labels 或 generation 输入

4. 语言模型生成
   - 调用 forward / generate
   - 输出文本序列
   - 输出 hidden states

5. 兼容性检查
   - 新版 transformers 下 forward 和 generate 的行为是否一致
   - hidden_states 的结构是否仍满足 LISA 的使用方式

4.3 LLaVA 模块的推荐阅读顺序
--------------------------
建议顺序不是按目录顺序，而是按“理解链路最短”的顺序：

1. chat.py
   - 先看总流程，知道所有模块怎么被串起来。

2. model/llava/mm_utils.py
   - 先弄清 <image> 是如何进 tokenizer 的。

3. model/llava/conversation.py
   - 再弄清 prompt 模板是如何构造的。

4. model/llava/model/llava_arch.py
   - 再看图像特征是如何插到语言模型里的。

5. model/llava/model/language_model/llava_llama.py
   - 再看 forward / generate 和 hidden states 的返回。

6. model/llava/model/multimodal_encoder/clip_encoder.py
   - 最后补 vision tower 细节。

4.4 如果把 LLaVA 这一块写成 TODO LIST，应该怎么排
----------------------------------------------
[ ] 看 chat.py，画出图文输入到文本输出的总流程
[ ] 看 mm_utils.py，确认 <image> 占位符如何转成 image token
[ ] 看 conversation.py，确认 prompt 模板和 special token 的使用方式
[ ] 看 llava_arch.py，确认图像特征如何插入文本 embedding
[ ] 看 llava_llama.py，确认 generate 与 hidden states 的输出形式
[ ] 看 clip_encoder.py，确认 vision tower 的输入输出张量形状
[ ] 独立写出一个“只做图文输入和文本生成”的最小 LLaVA 推理版本
[ ] 在新版 transformers 下验证 generate / hidden_states 行为是否兼容
[ ] 判断旧版 LLaVA 封装哪些能保留，哪些必须重写


五、LISA bridge 模块详细拆解
---------------------------
这一部分是 LISA 特有能力，不是通用 LLaVA 的一部分。

5.1 关键文件
-----------
1. model/LISA.py
   - 作用：LISA 主模型。
   - 负责把 LLaVA 和 SAM 串起来。

2. model/LISA.py 中的 initialize_lisa_modules()
   - 作用：初始化 SAM 和 text_hidden_fcs。

3. model/LISA.py 中的 evaluate()
   - 作用：推理阶段总入口。
   - 包含生成、[SEG] 定位、prompt embedding 生成、mask 解码。

5.2 子任务拆解
-------------
1. 确认 [SEG] token 的 tokenizer 表示
2. 确认输出序列中如何找到 [SEG]
3. 确认如何取出 [SEG] 对应 hidden state
4. 确认 text_hidden_fcs 的输入输出维度
5. 确认 text_hidden_fcs 输出如何送入 SAM prompt encoder

5.3 推荐 TODO 顺序
----------------
[ ] 看 model/LISA.py 的整体结构
[ ] 只抽取 evaluate() 推理路径，不看训练路径
[ ] 确认 [SEG] token 的定位方式
[ ] 确认 hidden state 到 text_hidden_fcs 的映射
[ ] 画出 LLaVA 输出到 SAM 输入的桥接链路


六、fine-tuning / 权重适配模块详细拆解
----------------------------------
这一部分虽然不属于最终推理前向本身，但它决定了你最后拿来推理的权重是否完整。

6.1 关键文件
-----------
1. merge_lora_weights_and_save_hf_model.py
   - 作用：展示 LoRA 权重如何与 base model 合并，并导出可直接推理的 HF 格式模型。

2. train_ds.py 中的模型构建部分
   - 作用：帮助确认哪些层会参与 fine-tuning，哪些层被冻结。
   - 这里只看模型装配与参数设置，不复刻完整训练流程。

3. model/LISA.py 中与参数初始化、可训练模块相关的部分
   - 作用：确认 text_hidden_fcs、mask decoder 等模块在原方案中的训练角色。

6.2 子任务拆解
-------------
1. 理清 base model 的组成
2. 理清需要 fine-tune 的模块
3. 理清最终推理所需加载的权重集合
4. 理清 LoRA merge 或等价权重导出流程
5. 理清在新环境下是否需要重写这套权重组织方案

6.3 推荐 TODO 顺序
----------------
[ ] 看 model/LISA.py，确认哪些模块是新增可训练模块
[ ] 看 train_ds.py 中的模型构建与参数冻结逻辑
[ ] 看 merge_lora_weights_and_save_hf_model.py，确认推理前的权重合并路径
[ ] 整理“推理需要哪些权重”的最终清单
[ ] 判断这部分在新环境下哪些能参考，哪些需要重写

九、可直接复用与只能参考的判断标准
--------------------------------
1. 可以直接复用
   - 对 torch / transformers 版本不敏感
   - 主要依赖基础 PyTorch 张量运算
   - 不依赖旧版 LLaVA 私有封装细节

2. 只能参考，最好重写
   - 强依赖旧版 transformers==4.31.0
   - 强依赖旧版 generate / hidden_states 行为
   - 强依赖 deepspeed / bitsandbytes / 旧版量化路径
   - 强依赖旧版 fine-tuning / merge 脚本接口
   - 含明显硬编码，或假设老版本框架内部行为不变


十、当前结论
-----------
1. SAM 模块整体更接近“可直接复用”。
2. LISA bridge 的思想可以直接复用，但实现需要重新整理。
3. 旧版 LLaVA 封装整体更适合作为“参考实现”，不建议直接照搬。
4. fine-tuning / merge 相关脚本需要纳入范围，但更适合作为“权重组织参考”，不适合直接原样复用。
5. 因为原仓库锁定 torch==1.13.1、transformers==4.31.0，所以在 torch 2.8.0 + CUDA 12.8 环境下必须重新做兼容性判断。
